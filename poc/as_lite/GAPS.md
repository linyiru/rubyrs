# ActiveSupport-lite spike — gap inventory

Generated by running `poc/as_lite/spike.rb` under both CRuby
(`ruby` + `active_support/all` 8.0.1) and rubyrs (stock — no
`active_support_lite.rb` canon yet). The `[OK]` / `[GAP]` lines
in the spike output classify each idiom; this file groups them
into tiers by the effort needed to close the gap.

## Tier A — trivial pure-Ruby method adds (one-liner each)

These need no VM work; each is 1–3 lines in
`src/stdlib_vendor/active_support_lite.rb` once the file lands.

| Method | Affected classes | Canon impl shape |
|---|---|---|
| `blank?` | NilClass, TrueClass, FalseClass, String, Array, Hash, Numeric, Object | `nil/false → true`; primitives `false`; `String → !!match?(/\A\s*\z/)`; `Array/Hash → empty?` |
| `present?` | (mixin on Object) | `!blank?` |
| `presence` | (mixin on Object) | `blank? ? nil : self` |
| `Array#second/third/fourth/fifth` | Array | `self[1] / [2] / [3] / [4]` |
| `Array#in_groups_of(n, fill = nil)` | Array | iterate, pad with `fill` (or drop trailing when `fill == false`) |
| `Object#try(*args, &block)` | Object, NilClass | `respond_to? ? send : nil`; NilClass always nil |
| `Object#in?(collection)` | Object | `collection.include?(self)` |

**Estimated**: ~50 LOC. Zero VM gaps surfaced.

## Tier B — String methods (Regexp-dependent, no VM gap)

rubyrs ships Regexp via the `regex` default feature, so these are
all expressible in pure Ruby. Two of them (`camelize`,
`underscore`) interact with each other and `titleize` /
`humanize` build on them; ordering matters but no surprises.

| Method | Canon impl shape |
|---|---|
| `String#blank?` | `match?(/\A\s*\z/)` — whitespace-only test |
| `String#squish` | `gsub(/\s+/, ' ').strip` |
| `String#camelize(first_letter = :upper)` | `gsub(/(?:_+)(\w)/) { $1.upcase }`, then upcase first if `:upper` |
| `String#underscore` | `gsub(/([A-Z]+)([A-Z][a-z])/, '\1_\2').gsub(/([a-z\d])([A-Z])/, '\1_\2').downcase` |
| `String#dasherize` | `tr('_', '-')` |
| `String#titleize` | `underscore.gsub('_', ' ').split.map(&:capitalize).join(' ')` |
| `String#humanize` | replace `_id` suffix + underscore-walk + capitalize first |
| `String#truncate(n, omission: '...', separator: nil)` | length-gate slice + omission append |

**Estimated**: ~80 LOC. Zero VM gaps. Probe ran cleanly through
the regex backend on rubyrs.

## Tier C — Hash methods (no VM gap; Hash transforms)

Hash#slice, #except, #transform_values, #transform_keys, #compact
ALREADY WORK on stock rubyrs (CRuby stdlib promoted them out of
ActiveSupport in 2.5 / 3.0). The remaining shapes are pure Ruby:

| Method | Affected | Canon impl shape |
|---|---|---|
| `Hash#symbolize_keys` / `#symbolize_keys!` | Hash | `transform_keys(&:to_sym)` |
| `Hash#stringify_keys` / `#stringify_keys!` | Hash | `transform_keys(&:to_s)` |
| `Hash#deep_symbolize_keys` | Hash | recurse: keys → sym, values → walk if Hash/Array |
| `Hash#deep_stringify_keys` | Hash | recurse: keys → str, values → walk |
| `Hash#deep_merge(other) { |k, a, b| … }` | Hash | recurse on Hash-vs-Hash; non-Hash overwrites |

**Estimated**: ~40 LOC. Zero VM gaps.

## Tier D — DEFERRED (Duration / TimeZone infrastructure)

These needed their own ADR before the canon attempt. Each one
chains through a real `Time` arithmetic / TZ DB / `Duration`
value type that ActiveSupport invented; matching the surface
without matching the implementation has nontrivial parity risks.

| Method | What it depends on |
|---|---|
| `3.minutes` / `1.day` / `2.hours` (Numeric duration helpers) | `ActiveSupport::Duration` value type |
| `2.hours.ago` / `1.day.from_now` | `Duration + Time` arithmetic |
| `Time.current` | TZ-aware "now" — depends on `Time.zone` |
| `Time.zone` | tzinfo DB + thread-local current zone |

**Decision**: defer entirely to a follow-up ADR (provisional 0028
or thereabouts). The Rack/Sinatra/JSON menu items work without
them; the apps that need timezone math should reach for menu
item 4 (SQLite-backed data layer) where dates are an explicit
column type, not a `Numeric#days` afterthought.

If a Tier-A canon ships first and we later want a narrow Duration
slot just for the most-used `Numeric#minutes / #hours / #days +
Time` shapes, the `Duration` value type can live in pure Ruby
(no tzinfo) at the cost of dropping TZ-aware arithmetic — that's
a Tier-D-narrow sub-decision when the use-case appears.

## What does NOT need fixing

Already working on stock rubyrs (no canon needed):

- `Hash#slice`, `#except`, `#transform_values`, `#transform_keys`,
  `#compact` (stdlib since Ruby 2.5 / 3.0)
- `Array#first(n)` (built-in)
- `Range#to_a` (built-in)

## No VM gaps surfaced

Notably, the spike found **zero VM-level missing features**. The
spike's prior expectations (regex support? method_missing for
`try`? Range integration?) all worked out of the box because of
prior M27 / pass-N work. Every gap is a missing pure-Ruby method
definition on a built-in class — exactly the shape
`src/stdlib_vendor/active_support_lite.rb` is designed to host.

Contrast with M27 D (Sinatra) where the spike drove **A1/A2/A3/A4
+ B1/B2 + C1 VM batches** before the canon could ship; this menu
item is closer to JSON in shape — pure-Ruby canon is sufficient,
and any future accelerator is optional perf work, not a
correctness requirement.

## Next commits (if menu item 3 proceeds)

In priority order:

1. `feat(stdlib): pure-Ruby active_support_lite canon — Tier A + C`
   — `blank?` / `present?` family + Array second/third/fourth +
   `in_groups_of` + `Object#try/#in?` + Hash symbolize/stringify
   /deep variants + deep_merge. ~90 LOC, zero VM work.
2. `feat(stdlib): active_support_lite Tier B — String slice`
   — camelize / underscore / dasherize / titleize / humanize /
   truncate / squish / blank?. ~80 LOC.
3. `test(diff_framework): as_lite_canon fixture` — same shape as
   `json_canon`, byte-diffs against `active_support/all` on the
   CRuby side. Probably one or two ratchet rounds to clean up
   edge cases (camelize on multi-underscore, humanize on `_id`
   suffix, deep_merge with array values, etc.).
4. (optional, later) Duration value type — narrow Tier D — only
   if a real consuming fixture (e.g. menu item 4 SQLite data
   layer wanting `Time.now + 1.day` syntax) demands it.

Total scope estimate: ~170 LOC canon + ~50 LOC fixture + 2–3
parity-fix commits = **3 atomic commits, ~1 work day**. ADR's
3–5 day estimate was for a fuller core-ext slice including
Duration; the spike's "defer Tier D" call brings the practical
scope down to under that.
